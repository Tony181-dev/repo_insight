Đọc workspace repo sync như đọc một bản vẽ

repomap vẽ cây repo từ manifest, rồi chỉ đọc sâu vào chỗ bạn bấm: một repo, một nhóm file build, một file và những file nó kéo theo. Chạy ngay trên máy build vừa repo sync, không cần build, không cần mạng.

Bản vẽ trên là bản thu nhỏ của giao diện thật, dùng một workspace mẫu. Bấm vào các node có viền đỏ đứt nét để đi qua từng tầng.

Bốn tầng, chỉ nạp khi bạn cần

Một workspace Android hay Yocto có thể có vài nghìn repo. Quét hết mọi thứ lúc mở thì chậm và phần lớn thông tin bạn không dùng tới. repomap tách việc đọc thành bốn tầng; tầng sau chỉ chạy khi bạn bấm vào đúng chỗ đó, và kết quả được giữ lại cho lần bấm sau.

  1. 0Khi mở

    Cây repo

    Đọc .repo/manifest.xml cùng các file include, local_manifests, remove/extend-project. Mỗi repo được tô màu theo loại, nhận ra bằng vài file đánh dấu ở thư mục gốc.

  2. 1Bấm một repo

    Thông tin nhanh

    Commit đang checkout, số file đang sửa, thông tin chính theo loại repo: layer Yocto, BoardConfig, phiên bản kernel, variant QNX. Kèm danh sách file chính.

  3. 2Bấm Quét sâu

    Toàn bộ file build

    Liệt kê mọi file bằng git ls-files và gom nhóm: recipe, bbappend, machine, Android module, defconfig, device tree, buildfile QNX, CMake, Makefile…

  4. 3Bấm một file

    File và tham chiếu

    Biến, module, nội dung, và các file được kéo theo đã tìm ra đường dẫn thật. Bấm tiếp để đi sang file đó, kể cả khi nó nằm ở repo khác.

Chạy ở đâu

repomap phải chạy trên máy đang chứa source code, tức thư mục bạn đã repo sync về, vì nó đọc trực tiếp manifest, Makefile, file .bb… trên ổ đĩa.

Không cài lên board. Board chỉ chạy image đã build xong; trên đó không có source nên tool không có gì để đọc.

Trong các lệnh trên trang này, thay các tên mẫu bằng giá trị thật của bạn:

  • ~/your_workspace_root: thư mục gốc bạn đã chạy repo init và repo sync, bên trong có thư mục .repo/. Ví dụ ~/projects/android13.
  • your_build_server: tên hoặc địa chỉ IP của máy build bạn ssh vào.
  • user: tài khoản ssh của bạn trên máy build.
  • your_repo_url: địa chỉ git của repo chứa tool này.

Tuỳ source nằm ở đâu, chọn một trong hai cách.

Cách 1: source nằm trên PC Linux bạn đang ngồi

python3 -m repomap ~/your_workspace_root

Trình duyệt tự mở tại http://127.0.0.1:8800. Không cần ssh.

Lấy tool bằng git clone your_repo_url rồi chạy lệnh trên trong thư mục đó, hoặc dùng file repomap.pyz đã đóng gói như ở cách 2.

Cách 2: source nằm trên máy build ở xa, bạn ssh vào

  1. Copy tool lên máy build: scp repomap.pyz user@your_build_server:~/bin/, hoặc git clone ngay trên máy đó.
  2. Trên máy build, chạy python3 ~/bin/repomap.pyz ~/your_workspace_root. Tool in ra một lệnh dạng: 
    ssh -L 8800:127.0.0.1:8800 user@your_build_server
  3. Trên PC của bạn, chạy lệnh đó rồi giữ cửa sổ terminal mở.
  4. Mở trình duyệt trên PC, vào http://127.0.0.1:8800.

Tool đọc file ở máy build, còn bạn xem giao diện trên PC qua ssh tunnel. Không phải copy source về PC.

Port, user và tên máy trong lệnh tunnel chỉnh được ở file cấu hình. Nếu port 8800 bận, tool tự chuyển sang 8801, 8802… và lệnh in ra theo port mới.

Đóng gói trên Windows

Bạn đóng gói tool một lần trên PC Windows thành một file repomap.pyz khoảng 35 KB, rồi copy file đó lên máy build. Máy build chỉ cần có python3, không cần git clone, không cần pip, không cần mạng.

  1. Cài Python 3.8 trở lên trên Windows từ python.org. Python này chỉ dùng để đóng gói.
  2. Lấy mã nguồn: git clone your_repo_url, hoặc tải file zip của repo rồi giải nén.
  3. Bấm đúp build.bat, hoặc chạy trong cmd: 
    build.bat           rem chạy unit test rồi đóng gói
build.bat notest    rem bỏ qua unit test
    Kết quả là file dist\repomap.pyz. Cửa sổ dừng lại ở cuối để bạn đọc kết quả, kể cả khi có lỗi; bấm phím bất kỳ để đóng.
  4. Copy lên máy build. Windows 10 trở lên có sẵn lệnh scp; dùng WinSCP cũng được. 
    scp dist\repomap.pyz user@your_build_server:~/bin/
  5. Trên máy build, chạy như cách 2 ở trên: 
    python3 ~/bin/repomap.pyz ~/your_workspace_root

File copy từ Windows sang sẽ không có quyền thực thi, nên chạy qua python3 repomap.pyz. Muốn gõ thẳng ./repomap.pyz thì chạy chmod +x một lần.

Đóng gói trên Linux

make pyz                     # chạy test rồi đóng gói
python3 tools/build_pyz.py   # không cần make

Cả hai đều tạo dist/repomap.pyz giống hệt bản của build.bat, vì cùng dùng script tools/build_pyz.py.

Máy build không có Python 3.8

Kiểm tra trước bằng python3 --version. Máy build Yocto hay Android thường đã có sẵn python3. Nếu thiếu hoặc quá cũ, các cách dưới đều không cần quyền root:

  • Android: sau repo sync thường có Python dựng sẵn trong prebuilts/. Tìm bằng find prebuilts -path '*linux-x86*' -name 'python3*' -type f, rồi chạy file .pyz bằng Python đó.
  • Yocto: chạy poky/scripts/install-buildtools để tải bộ buildtools có python3 mới, sau đó source file môi trường mà nó in ra.
  • Python riêng trong thư mục home: giải nén một bản Python dựng sẵn cho Linux (dự án python-build-standalone, hoặc Miniforge) vào ~/opt/python, rồi chạy ~/opt/python/bin/python3 repomap.pyz ~/your_workspace_root.
  • Chạy trên PC thay vì máy build: gắn source về PC bằng sshfs your_build_server:your_workspace_root ~/your_workspace_root rồi chạy repomap trên PC. Nút Quét sâu với repo lớn sẽ chậm hơn vì file phải đọc qua mạng.

Không cần giao diện

python3 repomap.pyz ~/your_workspace_root --json kernel/linux > linux.json

In ra thông tin nhanh và kết quả quét sâu của một repo dưới dạng JSON, tiện để đưa vào script.

Cấu hình

Tạo file mẫu có sẵn chú thích, rồi sửa những dòng cần thiết:

repomap --init-config

File được ghi vào ~/.config/repomap/config.ini. Muốn để cấu hình riêng cho một thư mục, đặt file tên repomap.ini ở đó, hoặc chỉ định bằng --config.

Tham số dòng lệnh luôn thắng file cấu hình: --port, --host, --no-browser, --workers.

Thứ tự tìm file: --config, biến $REPOMAP_CONFIG, ./repomap.ini, rồi ~/.config/repomap/config.ini.

[server]
host = 127.0.0.1     # 0.0.0.0 mở cho cả mạng, không có mật khẩu
port = 8800
port_tries = 20
open_browser = auto  # auto, yes hoặc no

[ssh]                # dùng để in lệnh tunnel
local_port =         # trống: giống port server
user = dev
host = your_build_server

[scan]
workers = 0          # 0: tự chọn theo số CPU

Hệ được hỗ trợ

Mọi thứ là phân tích tĩnh trên file nguồn, nên dùng được ngay sau repo sync. Bảng dưới là những gì repomap nhận ra và đọc được ở từng tầng.

HệNhận ra nhờTầng 1 cho biếtTầng 3 nối được
Yocto, BitBake conf/layer.conf, meta-*/conf/layer.conf, bitbake/bin/bitbake Collection, priority, LAYERDEPENDS, LAYERSERIES_COMPAT, machine, distro, các thư mục recipes-*, phiên bản BitBake require, include, inherit sang class ở mọi layer; recipe với các bbappend của nó; SRC_URI sang repo trong manifest
Android AndroidProducts.mk, BoardConfig*.mk, Android.bp, Android.mk PRODUCT_MAKEFILES, COMMON_LUNCH_CHOICES, TARGET_ARCH, TARGET_CPU_VARIANT, TARGET_BOARD_PLATFORM, module ở gốc repo inherit-product sang file .mk ở repo khác; module trong Android.bp và Android.mk kèm thư viện phụ thuộc
QNX Thư mục nto/, file .use, Makefile gọi recurse.mk hay qtargets.mk, buildfile có [virtual=] NAME, INSTALLDIR, LIBS, EXTRA_INCVPATH, các variant như nto/aarch64/so.le, thuộc tính image include từ Makefile của variant về common.mk
Linux, U-Boot Kconfig cùng arch/, kernel/, mm/ (U-Boot: board/, cmd/) Phiên bản từ Makefile, danh sách arch và số defconfig của từng arch #include trong device tree, source trong Kconfig
Các hệ khác CMake, Meson, Make, Autotools, Bazel, Cargo, Go, Gradle, Node, Python Tên project và target CMake, các biến chính trong Makefile add_subdirectory, include() của CMake, subdir() của Meson, include của Make

Giới hạn cần biết

  • repomap không chạy bitbake, make hay soong. Biến chỉ được thay ở các dạng đơn giản như $(LOCAL_PATH), ${THISDIR}, ${PN}; tham chiếu còn biến khác sẽ hiện nhưng không bấm sang được.
  • Override của BitBake và biểu thức ${@...} không được tính.
  • Thư viện phụ thuộc của Android module chỉ hiện tên, chưa nối sang repo định nghĩa module đó.
  • Mỗi nhóm file gửi tối đa 600 mục về giao diện; nội dung file hiện 4000 dòng đầu.
  • Workspace không có manifest vẫn dùng được: tool tìm các thư mục .git sâu tối đa 6 cấp.
